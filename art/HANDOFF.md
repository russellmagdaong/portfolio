# Art handoff (phases 4 and 5)

Revised 2026-11-16. The first pass (Codex drawing, logged below) came out too simple, and its signs weren't in English.
New split:

- **Codex is the art director.** It writes the concept for every file: what's in it, where, how it's lit, and the exact sign text. It doesn't draw the final art.
- **Claude draws** the `.aseprite` files from Codex's concepts.
- **Russell** approves each concept before Claude draws it, and each drawing before it counts as done.

Read `BRIEF.md` (style, including "Density" and "Lettering") and `README.md` (file setup) first.
The mood references are in `art/_work/refs/` (`skyline-rain.png`, `market-street.png`). They are copyrighted: study them, never trace or copy them, and never move them out of `_work/`.

## Codex: concepts

For each file, write `art/concept/<file>.md` (for example `art/concept/scenes-home.md`, `art/concept/map.md`, `art/concept/map-objects.md`). Each one has:

1. **Mood:** one paragraph, plus which parts of the references it borrows (for example "the fogged skyline layers of skyline-rain", "the clutter of signs and vending machines in market-street").
2. **Layer by layer, back to front** (`sky`, `far`, `mid`, `back`, `floor`, `props`, `front`): what's in each, with rough x ranges on the canvas. Respect the existing slices (read them from the file; a script can list them) and say what stands at each `object:` and `platform` slice.
3. **Light:** the main light, the scene's neon accent colour(s), where the reflections and fog go.
4. **Every sign, word for word, in English,** with its size (3x5 or 5x7), colour and position. Invent names; no real brands.
5. **Animation:** at most a few loops per screen (rain, a flickering sign, a blinking antenna light), with frame timings.
6. **A colour block-out:** a small PNG at the file's real size in `art/_work/concept/<file>.png`, made with flat palette colours only (shapes and values, no detail), so Claude and Russell can see the composition.

Also write `art/concept/palette.md` if the references need colours the palette lacks (likely: foggy blue-teal greys for distant layers). Propose them there; Claude adds them to the end of `palette.gpl` after Russell agrees.

**Order:** palette, then `scenes/home`, then `scenes/arcade`, then the map and map objects, then the other four scenes. Log each concept below as "concept ready". Codex edits only `art/concept/` and `art/_work/concept/`.

## Claude: drawing

- Draw a file only after its concept is logged as "concept ready" and Russell has okayed it.
- Draw through Lua scripts in `scripts/art/draw/<file>.lua` (batch mode, `C:\aseprite\build\bin\aseprite.exe -b --script ...`), so a file can be redrawn. Codex's first-pass scripts there can be reused for shared parts (like the lettering) or replaced.
- **Keep every slice and every layer's user data as they are.** If one has to move to fit the art, move it and log it.
- After each file: `npm run art -- <path without .aseprite>`, fix its warnings, and compare the 4x export against the concept block-out and the references.
- Russell also edits these files by hand. Before re-running a script on a file, check whether he changed it, and ask first.

## Rules for everyone

- Only colours from `palette.gpl`.
- Never put template or reference pixels in a committed file.
- Don't commit, and don't run git commands that change anything.
